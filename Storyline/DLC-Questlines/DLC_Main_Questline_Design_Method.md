# DLC Main Questline Design Method — Placeholder / Skeleton

**Status: no DLC plan exists for Toronto Fell Out yet.** This file is not a specification to run against
real content — it's a placeholder that establishes the *principle* to use once Toronto Fell Out has a DLC
structure worth designing against. Adapted from Inner Tepenia's own `DLC_Main_Questline_Design_Method.md`,
which is heavily built on that game's specific worldbuilding-document taxonomy (per-city Cross-Reference
Synthesis sheets, a Megasheet/Ultra-Megasheet/Super-Ultra-Megasheet layer, a Local_Cultures folder
hierarchy). **Toronto Fell Out has no equivalent of any of that**, and this file deliberately does not
invent fake document-hierarchy names to fill the gap.

**Companion document:** `But_Therefore_Quest_Design_Method.md` (same folder) — this file governs which
inputs would feed a DLC main-questline's But/Therefore chain once real DLC content exists; that one
governs the chain-construction grammar itself, and carries over to Toronto Fell Out largely unchanged.

---

## The Portable Principle

Strip away Inner Tepenia's specific document names and what's left is a genuinely reusable idea, worth
keeping as a standing method:

1. **Gather structured inputs** from whatever established canon exists for the DLC's subject matter —
   not invented fresh, and not the full text of every source document, but the load-bearing findings,
   conclusions, and open threads already on record for it.
2. **Construct multiple candidate But/Therefore chains** (per `But_Therefore_Quest_Design_Method.md`)
   from those inputs — not just one. Inner Tepenia's own method specified "at least 10" candidates per
   DLC; the exact number matters less than the discipline of generating several and picking the
   strongest rather than running with the first idea.
3. **Filter candidates against two criteria:**
   - **Non-conflicting** — doesn't contradict anything already established, and doesn't require an
     established fact to be quietly ignored to work.
   - **Characteristically consistent** — reads as something that could only happen in *this* specific
     place/faction/context, grounded in whatever's already been established about its identity and
     relationships, not a generic conflict that could be relocated anywhere without losing anything.
4. **Prefer emergent chains over invented ones.** The strongest candidate chains visibly trace back to
   specific already-established facts rather than dropping a new idea on top of them. A small, solid
   questline beats a long, complex, incoherent one every time.

This is the part of Inner Tepenia's method worth keeping regardless of how Toronto Fell Out's own DLC
structure eventually shapes up — it's a discipline for turning existing canon into quest content, not a
discipline tied to any particular document taxonomy.

---

## What's Not Carried Over

Inner Tepenia's version of this method names eight specific input sources (city-level and subnet-level
Cross-Reference Synthesis sheets, Cross-City/Cross-Regional Throughways, Full Extrapolation sheets,
city-level lore-history files, Local Cultures city sheets, the Super-Ultra-Megasheet). **None of these
have a Toronto Fell Out equivalent**, and inventing placeholder names for them here would misrepresent
how much worldbuilding-documentation depth Toronto Fell Out actually has. When Toronto Fell Out's own
canon deepens enough to support DLC-scale content, the actual input list should be built from whatever
documents that canon has actually produced by then — likely a much shorter list, given Toronto Fell Out's
current scope (one setting, one city, no confirmed districts or factions yet).

---

## When This Becomes Relevant

Toronto Fell Out has no DLC plan of any kind at this stage — no confirmed subject matter, no confirmed
count, nothing analogous to Inner Tepenia's per-subnet DLC breakdown. This file should stay a skeleton
until at least one DLC concept exists to run the four-step principle above against. At that point:

1. Identify what canon actually exists for that DLC's subject matter (likely: relevant sections of
   `Reference/Main-Storyline-Candidates.md`, whatever district/faction material exists by then, and any
   dedicated DLC-concept document written for it).
2. Run Step 2–4 above against that material.
3. Hand the winning candidate chain to `But_Therefore_Quest_Design_Method.md` for full beat construction.
